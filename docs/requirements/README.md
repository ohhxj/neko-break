## 需求进入流程

1. 每个新功能、优化点、bug 修复想法或调研问题，先写入飞书多维表格「需求管理 / 需求池」。
2. 为需求补齐来源、状态、优先级、负责人、预估工作量、依赖、排期阶段、验收标准和关联链接；如果信息不足，状态标记为 `待澄清`。
3. 需要展开说明的需求，在飞书中新建独立 PRD 文档，内容包含背景、目标、用户场景、功能范围、非目标、交互/技术注意点和验收标准。
4. 把独立 PRD 文档链接回填到飞书多维表格对应记录的 `PRD 文档` 或 `关联链接` 字段。
5. 实现后更新飞书多维表格中的需求状态，并补充代码、测试、发布说明或后续需求链接。

## 状态值

- `已提出` - 已记录，但还没有完成评估。
- `待澄清` - 需要补充产品、交互或技术细节。
- `已就绪` - 信息足够清楚，可以排期或交给开发任务。
- `进行中` - 正在设计、调研或实现。
- `已上线` - 已实现并通过验收。
- `暂缓` - 明确暂时不排期。
- `放弃` - 不再计划实现。

## 优先级

- `P0` - 关键正确性、数据丢失、核心路径不可用或紧急发布阻塞。
- `P1` - 高影响产品能力或严重体验问题。
- `P2` - 有明确价值，但可以进入计划迭代的改进。
- `P3` - 锦上添花、视觉细节或探索性想法。

## 工作量

- `S` - 通常小于半天。
- `M` - 大约一到两个专注工作日。
- `L` - 需要数天，或涉及多个模块。
- `XL` - 需要先拆分，再进入排期。

## 复盘节奏

每新增 3 个以上需求、开始新的开发批次前、或某个需求上线后产生后续工作时，都应该复盘一次需求池。复盘时按影响、风险、成本和依赖重新排序，不按提出顺序盲目开发。
